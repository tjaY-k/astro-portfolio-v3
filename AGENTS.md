# AGENTS.md

## Project Overview
Это профессиональное портфолио Константина Лаптева — Video Technical Manager и Senior disguise (d3) Operator.
Сайт должен производить сильное впечатление на потенциальных клиентов, работодателей и партнёров в сфере live events, immersive technology, projection mapping, xR/virtual production и broadcast.

Главная цель — показывать экспертизу через кейсы, качество исполнения и профессиональную подачу.

## Tech Stack
- Astro 4+
- TypeScript (strict mode)
- Tailwind CSS
- Custom components и модалы
- 3D элементы (Three.js / Svelte или Astro-совместимые решения)
- **Cloudflare Pages** (деплой через GitHub)
- Опционально: View Transitions, prefetching

## Deployment
- Основной деплой происходит автоматически через **GitHub → Cloudflare Pages**.
- При работе с конфигурацией деплоя (wrangler.toml, _headers, _redirects, build settings) — будь особенно внимателен.
- После любых изменений в инфраструктуре деплоя — проверяй, что production-сборка успешно проходит.

## Project Structure & Conventions

```
src/
├── components/          # Переиспользуемые UI-компоненты
├── layouts/             # Layouts (BaseLayout, ProjectLayout и т.д.)
├── pages/               # Страницы
├── content/             # Content Collections (проекты, ресурсы)
├── lib/                 # Утилиты, helpers, типы
├── styles/              # Глобальные стили
└── assets/              # Изображения, видео, 3D-модели
```

**Правила именования:**
- Компоненты: `PascalCase.astro` или `PascalCase.svelte`
- Утилиты и типы: `camelCase.ts`
- Файлы контента: `kebab-case.md`
- Изображения: осмысленные названия на английском

## Code Style & Quality Rules

- **TypeScript strict** — никаких `any` без крайней необходимости.
- Пиши **чистый, читаемый код**. Комментарии только там, где логика неочевидна.
- Все компоненты должны быть максимально переиспользуемыми.
- Избегай deeply nested компонентов без необходимости.
- При работе с данными — используй Content Collections где возможно.
- Все новые фичи и большие изменения — только после утверждения плана.

## Component Guidelines

- **Модалы и overlay-элементы**: Должны быть доступными (keyboard navigation, focus trap, aria-атрибуты).
- **Project cards / ResourceItem**: Сохраняй единообразие стиля и поведения.
- При добавлении новых секций — старайся вписывать их в существующую визуальную систему.
- 3D-элементы: следи за производительностью (ленивая загрузка, правильный cleanup).

## Content & SEO

- Весь публичный текст — на **английском** (высокий уровень).
- Заголовки и мета-данные должны быть SEO-friendly.
- При добавлении новых проектов — обязательно заполняй:
  - Короткое описание
  - Роль и задачи
  - Технологии и оборудование
  - Результат / масштаб (если есть цифры)
- Избегай клише. Подача должна быть профессиональной и конкретной.

## Design & UX Rules

- Сайт должен выглядеть **современно, минималистично и профессионально**.
- Сохраняй существующий визуальный язык (типографика, отступы, акценты).
- Много воздуха + чёткая иерархия.
- Анимации — умеренные и purposeful (не ради анимации).
- Мобильная версия — не secondary, а полноценная.

## When Working on This Project (Важно!)

1. **Сложные задачи** — всегда сначала предлагай план изменений.
2. Показывай, **какие файлы** будут затронуты и почему.
3. После реализации — давай краткое summary: что было сделано и почему именно так.
4. Если предлагаешь рефакторинг — объясняй выгоду (производительность, maintainability, DX).
5. При работе с контентом — сохраняй tone of voice: профессиональный, уверенный, без воды.

## Preferred Approach

- Предпочитаю **итеративный** подход: сначала структура → потом детали.
- Для визуальных изменений желательно показывать, как это будет выглядеть (описание + структура компонентов).
- Если есть несколько вариантов решения — предлагай 2–3 варианта с плюсами/минусами.

## Out of Scope (пока)

- Полная переработка дизайна без явного запроса
- Добавление тяжёлых зависимостей без необходимости
- Изменение структуры URL'ов без обсуждения
- Изменения в настройках Cloudflare Pages без явного согласования
